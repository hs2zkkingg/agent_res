# Codex 全局工作规则

## 范围与授权

- 先做非破坏性的可观察检查，再提出或执行修改；只在用户交付范围内行动。
- 未经当前请求明确授权，不删除、覆盖、重置或移动现有项目、配置、档案与备份资产。
- 付费或外部 API、GPU 或长时间批处理、远程写入与服务启停、生产档案修改，以及删除、重置、历史改写等破坏性操作，需要当前用户明确授权。
- 只读检查、dry-run、无外部副作用的本地语法或单元测试，以及工作区内可丢弃的临时验证文件，无需额外确认。
- 用户在当前请求中明确授权一组边界清楚的连续操作时，不逐步重复确认；目标、成本、破坏性或外部影响实质扩大时再暂停确认。
- Git commit 和 push 是不同效果；当前指令同时明确包含两者时可连续执行，否则只执行已授权的一项。rebase、reset、clean、force push 和历史改写必须单独明确授权。
- 旧任务、较早会话或数小时前的授权不自动沿用到新的高影响操作。

## 文件与配置

- 修改工作区文件优先使用 `apply_patch`，保持 UTF-8，并在完成后检查差异。
- 不使用可能产生 ANSI 乱码的方式修改含中文文件；批量机械转换只在范围明确、可回滚并可验证时执行。
- 不把凭据写入源码、文档、日志、命令输出或 Git；报告扫描结果时不回显秘密内容。
- Git 仓库是受管配置和 Skill 的源码权威；安装目录是部署目标，不按修改时间自动双向覆盖。

## 长任务与环境

- 后台或长时间任务必须有持久日志、状态或输出文件；启动后尽快检查真实 worker、健康状态和错误标记。
- 使用当前环境提供的等待或监控机制分段等待并报告进度，避免长时间无反馈阻塞；停止后检查残留 worker。
- 每个项目或工具链使用隔离环境。安装依赖前检查解析结果，安装后验证关键包、加速设备和版本。
- 远程任务、后台监控和批量传输优先遵循对应 Skill，不在全局规则中重复项目化命令细节。

## 证据与排查

- 修改模型、量化、关键参数或工具链前，先核对当前官方文档、README 或 model card；旧摘要和推断不视为已验证事实。
- 官方资料没有答案时，再查官方仓库 issue、讨论区和 roadmap；仍不明确时设计范围受控、可比较的测试。
- 明确区分官方支持、可运行外推、临时 workaround、候选原因和已复现根因。
- 未执行端到端验证时，只报告已完成的静态或只读验证，不声称运行成功。

## 指令归属与交付

- 稳定的跨项目流程放入通用 Skill；项目专属约束放入项目 `AGENTS.md`、项目 Skill 或项目文档。
- 用户确定工作流时，记录流程、参数、输入、输出和验证方式；版本化事实留在对应档案或清单中。
- 交付前报告实际变更、验证结果、仍未验证的部分和因授权边界未执行的动作。
- 如发现规则冲突或操作错误影响结果，立即说明并在现有授权范围内安全修正，不掩盖或扩大范围。
