# MiniMax H3 官方 API 长镜头（一镜到底）拼接备忘

> 2026-08-13 定案。适用：**官方 API**（`POST /v2/video_generation`, model=MiniMax-H3）生成 >15s 连续长镜头。H3 原生单段上限 15s，用 A-B-A 三明治拼接延长。
> 本地 vllm-omni 部署的出片规范见 `minimax-h3-ref2va` skill，本 skill 只讲官方 API 拼接。

## ⚠️ 核心机制（开工前必须懂）

| 官方 API role | 机制 | 帧锚定 |
|---|---|---|
| `reference_image`（ref2va） | 内容/身份软参考（≤9 图 + 视频≤3 + 音频≤3） | ❌ 无首帧锚定 |
| `first_frame`（i2va/FL2VA） | 首帧锚定 | ✅ 帧级精确（keyframes bind target geometry） |
| `last_frame` | 末帧锚定 | ✅ |
| `first_frame`+`last_frame` | 首尾双锚定 | ✅ |

- **互斥规则**：同一请求里 `first_frame`/`last_frame` 与 `reference_*` 不能混用（官方文档硬性规定）
- **质量结论**：FL2VA 与 Ref2VA 是同一 33B 底座的两个任务 checkpoint，画质无档位差——差异在条件强度（ref2va 多图身份稳 / fl2va 帧锚定准），不在画质
- 单图不带 role 默认按 `first_frame` 处理

### 官方 API 参数要点
- `duration`：4-15 **整数秒**
- `ratio`：i2va 段恒为 `adaptive`（跟随首帧图比例，传别的值被忽略）；ref2va 段可显式指定（21:9/16:9/4:3/1:1/3:4/9:16）
- `resolution`：768P / 2K；**无 seed 参数**（重试不复现）
- 计费：768P 0.5 元/s，2K 0.8 元/s
- 锚定帧上传：data URI（PNG 1-2.5MB）或 `mm_file://{file_id}`，body 限额 64MB 无压力

## A-B-A 三明治方案（流程定义）

**本质**：ref2va 段定期重置角色身份（防漂移），fl2va 短桥用首尾帧把两段 ref2va 粘起来（帧级无缝）。

```
第1轮（并行）: A ref2va | C ref2va | E ref2va ...（各自用同一套角色参考图）
              → 提取 A末帧、C首帧、C末帧、E首帧（SSIM 验收帧差）
第2轮（并行）: B fl2va: first_frame=A末帧, last_frame=C首帧
              D fl2va: first_frame=C末帧, last_frame=E首帧 ...
              → SSIM 自检锚定兑现
第3轮: concat 去重帧 + 目检 → 后期统一配音
```

- 桥段必须**等上游两段 ref2va 出片后**才能提交（锚定帧来自实际输出）
- 桥段锚定帧是文件、重试不受影响 → **桥段重试极便宜**（4s×0.8 元≈3.2 元）且边界被锚死，质检时大胆重试
- 重出一段 ref2va → 其**相邻两座桥作废**（止损最早：帧差验收在桥段开跑前）

## ⚠️ 三大坑（踩过才懂的）

1. **2K 升级炸链**：H3-Regenerate-2K 是重新生成不是超分，**不保帧一致**——A 升 2K 后末帧 ≠ B 的首帧锚定 → 全链接缝作废。**分辨率开工前定死**，全链统一（768P 或 2K），锚定帧必须来自最终分辨率版本
2. **VFR/重复帧**：H3 输出可能非常数帧率，且模型自身产生重复帧（社区 #74 实锤，真实风格也有）——**concat 前每段 `-vf fps=24` + `-vsync cfr` 归一**；模型自身重复帧交给 RIFE 插帧流程顺带清理
3. **末帧脏帧**：段末运动中末帧带运动模糊，直接当锚定帧会毒化下一段——**允许裁剪换缝点**，等式"锚定帧 = 剪辑后片段边界帧"成立即可；提取按**帧索引** + PNG 无损（`-vsync 0`），勿用时间戳 seek（H.264 易偏帧）

## 剧情编排规范（粘接/漂移友好）

- **shot card 纪律**：每段记录 开场状态 / 镜头运动 / 结束状态，段 i 的结束状态 = 段 i+1 的开场状态（手递手）
- **桥接点 80% 用"静止点"**：角色站定/休息/环境空镜——速度≈0 时无需匹配运动矢量、末帧最干净，最容易粘
- **留 1-2 座"动态桥"当风格点**：甩镜/物体擦过镜头，靠运动模糊藏缝（H3 擦镜处理不错）
- **时长分配**：ref2va 段 12-15s（发现漂移缩到 10-12s 加锚点密度）；桥 4-5s（帧差大给 5-6s 防 morph——桥太短+帧差大 = 快速变形）
- **漂移防御双墙**：① 每段 prompt 重复角色外观关键词（服装/颜色/配饰）+ 相同环境描述 ② ref2va 段同一套参考图

## 验收与后处理

- **帧差量化（不靠肉眼）**：A/C 出片后测 `A末帧 vs C首帧` SSIM，差距大 → 重出 A 或 C；B 出片后测 `B首帧 vs A末帧`、`B末帧 vs C首帧` 验证锚定兑现
- **concat**：`-map 0:v -an` 丢音轨（音频不参与，后期统一配）；每缝删 1 帧（41.7ms 无感）；B首帧与 A末帧存在 VAE 重建差，删或不删以实际观感定
- 音频策略：prompt 里 music/soundscape 写 N/A（少生成无用的音乐），后期统一 BGM/音效
- **chain manifest 归档**：段ID / 锚定帧文件 / prompt / 输出 mp4 / 边界帧提取物，对齐 IR 三件套归档纪律（多段链无索引必乱）

## 成本

- 公式：总时长 = Σ(ref2va 段) + Σ(桥段)；每桥 4-5s，ref2va 段 12-15s
- 例：64s 一镜 = 4×12s ref2va + 4×4s 桥 → 768P ≈32 元 / 2K ≈51 元；含重试按 ×1.3 预算

## 出片门禁（照搬 AGENTS.md gate 1）

- **每段提交前输出确认清单**：该段 role 模式（ref2va/i2va）、全部输入资产（参考图/首尾锚定帧路径）、duration、ratio/resolution、prompt、输出路径——用户明确确认后才提交
- 每段完成后：输出路径 + ffprobe + SSIM 验收结果 + 耗时
- 桥段依赖上游实际帧，**先确认上游出片完成再提交桥段**
